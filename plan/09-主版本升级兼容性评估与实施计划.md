# 主版本升级兼容性评估与实施计划

## 1. 目标

以 Vercel 部署的 Web 应用为唯一目标，围绕 Node 26、Next.js、React、API routes、SSE 和图片链路分阶段升级。Tauri、Docker 多平台发布和桌面安装包不属于当前验收范围。每个阶段集中修改、自动验证、更新本计划并提交 Git。

## 2. 当前基线与候选

当前基线为 Node 26、Next 16.4.5、React/React DOM 19.3.1、ESLint 10.14.0、TypeScript 5.2.2、Zod 3.24.1、Zustand 4.5.7。Vercel 通过 `vercel-build` 执行 Node 26 下的 webpack 生产构建。Tauri、Docker、TypeScript 7、Zod 4、Zustand 5、React Markdown 10 和 React Router 7 仅作为后续 Web 兼容性候选，不再作为当前发布阻塞项。

## 3. 实施阶段

- M0：记录候选版本、Node/peer 要求、Next 迁移点和回退边界。
- M1：升级 Next 16.4.5、React 19.3.1、ESLint 10 和 Node 26，迁移 flat config、异步 route params 与 webpack 构建。
- M2：完成图片生命周期和双击查看交互重构，修复升级暴露的运行时与类型问题。
- M3：建立 GitHub Actions 质量门禁；对 push、普通 PR 和手动触发执行 lint、Jest、TypeScript 和 Vercel 构建。
- M4：质量门禁通过后，由 GitHub Actions 使用 Vercel CLI 部署 preview 或 production；仅在 Vercel Web 链路中继续评估后续依赖升级。

## 4. 验收标准

每个阶段必须记录实际版本、失败尝试及回退原因。GitHub Actions 必须在普通 PR（opened/synchronize/reopened）和 `main` push 上执行 `yarn lint`、`yarn test:ci`、TypeScript 检查和 `yarn vercel-build`；只有质量任务通过后，才允许部署 Vercel preview 或 production。现有模型选择、首次授权、自定义接口/模型、图片上传/预览和流式响应测试不得回归。

## 5. 阶段记录

- M0（2026-11-06，已完成）：确认 Next 16.4.5 要求 Node `>=20.9.0`，ESLint 10 要求 Node 20.19/22.13/24；Node 26 作为长期目标保留在后续验证。Tauri 2、TypeScript 7、Zod 4、Zustand 5 等列为独立风险项。
- M1（2026-11-06，已完成）：升级到 Next 16.4.5、React 19.3.1、ESLint 10，迁移 flat config、React 19 类型、异步 route params 和 `next build --webpack`；同步升级 `@hello-pangea/dnd` 到 18.0.1，补充 IndexedDB SSR 能力判断，删除旧 `.eslintrc.json`/`.eslintignore`。Node 24 与 Node 26 Bookworm 容器中 lint、TypeScript、Jest 39/344 和生产构建均通过；Node 26 使用 `YARN_IGNORE_ENGINES=1` 进行基线验证后已纳入 engines、`.nvmrc`、`ensure-node.sh` 与 Dockerfile。构建仍有 Edge/preferredRegion 弃用提示，作为后续迁移项。
- M3/M4（2026-11-06，已完成配置）：新增 `package.json` 的 `vercel-build` 和 Vercel webpack 构建配置；将 GitHub Actions 收敛为 `.github/workflows/ci-cd.yml`，在普通 PR、`main` push 和手动触发时运行 Node 26 的 lint、Jest、TypeScript 和构建质量门禁，门禁通过后部署 Vercel preview/production。删除 Tauri/Docker/旧自定义预览发布 workflow，避免非 Vercel 平台流程继续阻塞 Web 迭代。生产 job 使用 GitHub `Production` environment，并在部署前检查 `VERCEL_TOKEN`、`VERCEL_ORG_ID`、`VERCEL_PROJECT_ID` 是否已配置。

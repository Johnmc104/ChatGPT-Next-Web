# 主版本升级兼容性评估与实施计划

## 1. 目标

在保持 Node 18.17–22.x、Web、Tauri、Edge route、SSE 和图片链路可用的前提下，分阶段评估并实施主版本升级。每个小阶段单独验证、更新本计划并提交 Git，避免依赖变更和业务修复混在一个提交中。

## 2. 当前基线与候选

当前基线为 Next 14.2.35、React 18.3.1、TypeScript 5.2.2、Tauri CLI 1.5.11、Zod 3.24.1、Zustand 4.5.7。候选主版本包括 Next 15.5.29/React 19.1.x、Next 16.x、Tauri CLI 2.x、ESLint 9/10、TypeScript 7、Zod 4、Zustand 5、React Markdown 10 和 React Router 7。

## 3. 实施阶段

- M0：记录候选版本、Node/peer 要求、Next 迁移点和回退边界。
- M1：先升级 Next 15.5.29、React 19.1.x 及配套 `@next/*`、类型包和 ESLint 配置，验证 lint、TypeScript、Jest、生产构建、Edge route、SSE 和图片 payload。
- M2：修复升级暴露的运行时或类型兼容问题；每个独立修复单独提交，并补充回归测试。
- M3：评估 Tauri 2、TypeScript 7、Zod 4 等独立主版本；若需要配置或 API 重构，建立独立提交和回退点。
- M4：Next 16 与 React 19 后续版本只在 M1/M2 稳定后评估，不能和 Tauri/TypeScript/Zod 同批升级。

## 4. 验收标准

每个阶段必须记录实际版本、失败尝试及回退原因；`yarn lint`、`yarn test:ci`、`yarn build` 通过，且现有模型选择、首次授权、自定义接口/模型、图片上传/预览和流式响应测试无回归。

## 5. 阶段记录

- M0（2026-11-06，已完成）：确认 Next 15.5.29 可在 Node 18.18+ 运行，React 19 为其正式 peer；Tauri 2、TypeScript 7、Zod 4、Zustand 5 等列为独立风险项。

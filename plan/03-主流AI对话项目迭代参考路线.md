# 主流 AI 对话项目迭代参考路线

## 1. 参考方法

当前项目已经具备统一代理、浏览器本地存储、Mask/提示词、MCP、实时语音、图片生成/编辑和 Tauri 桌面端。后续迭代应以“核心对话稳定、模型能力透明、扩展能力可插拔”为主线，参考主流 AI 对话产品常见的能力分层，而不是继续按 Provider 名称堆叠特例。

| 能力层 | 当前基础 | 迭代重点 |
| --- | --- | --- |
| 对话核心 | 流式输出、会话管理、Markdown/LaTeX/Mermaid | 统一消息协议、断线恢复、取消与重试 |
| 多模型 | OpenAI 兼容客户端、模型能力缓存、自定义模型 | capability registry、模型搜索、能力和价格提示 |
| 多模态 | 视觉输入、最多三张图片、图片生成/编辑 | 动态图片上限、文件输入、跨 Provider 图像解析 |
| 工具与知识 | MCP、插件、RAGFlow | 工具权限、调用过程展示、引用来源和可观测性 |
| 生产力 | Artifacts、Mask、导出、同步 | 文档/代码工作区、版本历史、分享权限 |
| 端与数据 | PWA、WebDAV、Tauri、本地优先 | 端能力一致、离线队列、加密备份和迁移 |
| 语音 | Realtime、TTS | 语音输入转写、打断、文本与音频消息统一 |

## 2. 推荐路线

### R0：稳定核心（优先级 P0）

先完成请求生命周期统一：请求 ID、AbortController、超时、重试、SSE 心跳和错误分类。会话消息应使用版本化 schema，确保模型切换、图片消息和旧数据迁移不会破坏历史记录。将关键指标写入本地调试日志：首 token 延迟、完成耗时、重试次数、图片处理耗时和失败原因。

### R1：模型与多模态（P0/P1）

把模型列表、能力、上下文长度、输入图片限制和工具支持放入同一 registry。模型选择器显示能力标签，并在发送前校验请求。优先完成新模型兼容和图像解析计划，再扩展文件输入；文件输入应复用 `ImagePart` 的资源生命周期和大小限制，而不是再建一套上传协议。

### R2：知识与工具工作流（P1）

在现有 MCP/RAGFlow 基础上增加工具确认、调用状态、结果引用和失败重试。搜索或文档问答必须展示来源，允许用户删除单条来源后重新生成，避免把工具结果永久混入会话上下文。

### R3：生产力工作区（P1/P2）

将 Artifacts、代码块预览、图片和文件结果统一为可操作的结果卡片，支持复制、下载、再次编辑和版本回退。Mask 继续作为提示词模板入口，但模型、工具、摘要模型等配置应能按会话覆盖，并且可导出。

### R4：跨端与商业化准备（P2）

Web、PWA、Tauri 共用 domain/service 层。同步采用增量记录和冲突策略，敏感配置只保存引用或加密数据。再评估团队空间、配额、审计和计费，避免在单用户数据模型未稳定前引入服务端状态。

## 3. 迭代节奏与验收

每个迭代限定一个用户结果和一个技术结果，例如“支持新视觉模型”同时要求模型能力测试、图片输入回归和错误提示。发布前执行 `yarn lint`、`yarn test:ci`、`yarn build`，并用固定 fixture 验证普通文本、工具调用、视觉输入、图片生成和编辑。

建议跟踪四类指标：核心请求成功率、首 token/图片完成延迟、模型能力误判率、活跃功能使用率。任何新 Provider 若需要修改通用聊天组件超过一个小范围，应先补 adapter；任何新文件或图片能力若没有大小、权限和生命周期策略，不进入默认开启状态。

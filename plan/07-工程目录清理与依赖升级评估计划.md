# 工程目录清理与依赖升级评估计划

## 1. 目标

降低根目录噪声，清理可再生的构建产物，保留 Next.js、Tauri、Docker、CI 和本地开发所需入口；依赖升级采用“先盘点、再分组、后验证”的方式，避免一次跨越 Next/React 大版本导致运行时回归。

## 2. 根目录处理边界

可删除的仅限被 `.gitignore` 忽略且可由命令重新生成的文件：`.next/`、`coverage/`、`tsconfig.tsbuildinfo`、`next-env.d.ts`、`yarn-error.log`。`node_modules/` 保留用于本地验证，`public/masks.json` 由 mask 构建生成但属于运行时静态资源，继续保留。根目录中的 `package.json`、`yarn.lock`、`next.config.mjs`、`tsconfig.json`、`jest.config.ts`、`Dockerfile`、`docker-compose.yml`、`vercel.json`、`src-tauri/` 相关入口不可删除。

## 3. 依赖升级策略

当前核心版本为 Next 14.1.1、React 18.2、TypeScript 5.2.2、Yarn 1.22.19，Node 约束为 18.17–22.x。先记录 `yarn outdated` 和 npm registry 的候选版本；补丁/小版本升级可单独提交，大版本升级必须先建立兼容分支并验证 Web、Tauri、Edge route、SSE、图片上传和 Jest。若升级要求 Node 23+ 或改变 React/Next 运行时，留在后续专门阶段。

## 4. 阶段记录

- D1：根目录生成物盘点与清理，验证 `git status`、`yarn lint`、`yarn test:ci`、`yarn build`。
- D2：依赖版本盘点，输出可升级清单，不在没有兼容性证据时直接升级大版本。

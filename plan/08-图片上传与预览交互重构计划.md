# 图片上传与预览交互重构计划

## 1. 目标

统一图片从选择、上传、状态、消息发送、历史展示到双击查看的生命周期。用户应能知道“准备中、上传中、成功、失败、重试、已发送”状态，双击图片只打开查看对话框，编辑框中的图片操作不应误触发消息编辑。

## 2. 现状与问题

`useChatImages` 已支持多图、拖拽、粘贴和失败重试，但上传结果主要以 URL 数组表示，缺少每张图片的状态和进度；发送失败时图片与草稿关系不够明确。`ChatMessageItem` 的双击逻辑、Markdown 图片和 `ImagePreview` 各自处理打开行为，编辑消息和图片查看的事件边界需要统一。底层缓存、Blob URL、服务端 `/api/cache` 和 Provider payload 也需要明确所有权。

## 3. 设计

引入 `ImageAttachment`：`id`、`fileName`、`mimeType`、`size`、`status`、`url`、`error`、`owner`。状态为 `queued → uploading → ready → sending → sent`，失败可重试，取消和切换会话释放未发送资源。预览卡片显示状态和错误；文本发送失败保留附件。双击预览调用统一 `showImageModal`，编辑按钮调用独立 `EditMessageModal`，事件使用 `stopPropagation`。

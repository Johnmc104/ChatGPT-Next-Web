# 代码清理与架构功能分析报告

## 1. 范围与基线

基线提交 `4fbb91fd`，GitHub Actions run `43374350165` 全部通过。`app/` 下共 175 个 TS/TSX 文件，约 29.3k 行。

本轮做三件事：

1. 按功能审查架构，盘点安全边界、模块耦合、已失效或越界的功能。
2. 用 `knip`（固定 `typescript@5.9.3`）扫描未使用的文件、依赖和导出。
3. 按第 5 节分阶段修复，每阶段验证后在第 7 节记录。

部署目标仍是 Vercel Web（`plan/11`）。

## 3. 发现

### 3.1 安全（P0）

| # | 位置 | 问题 | 影响 |
| --- | --- | --- | --- |
| S1 | `app/api/proxy.ts` + `common.ts` `resolveAuthHeaderValue` | 通用代理的上游地址取自客户端请求头 `X-Base-URL`。请求只带访问码时，`auth()` 返回服务端 `systemApiKey`，代理把它作为 `Authorization` 发给这个**由客户端指定**的地址。 | 任何持有访问码的人，在设置里填一个自定义接口地址，就能拿到服务端 API Key。插件请求同样经过这个代理。 |
| S2 | `next.config.mjs` `rewrites.beforeFiles` | `/api/proxy/{azure,google,openai,anthropic,alibaba}/…` 被直接改写到各厂商官方 API。改写发生在路由之前，完全绕过 `auth()`。代码中没有任何调用方。 | 公开的匿名中转，消耗本站带宽和 Vercel 额度，也可能被用于滥用。 |
| S3 | `app/api/artifacts/route.ts` | `POST` 不鉴权，任意内容写入 Cloudflare KV；`GET` 原样返回，供 Artifacts 页面按 HTML 渲染。 | 匿名用户可以在本站域名下托管任意 HTML（钓鱼页），并消耗 KV 额度。 |
| S4 | `app/api/model-info/refresh/route.ts` | 不鉴权即可触发服务端去 OpenRouter 拉取模型信息。 | 可被反复触发，放大外部请求。 |
| S5 | `proxy.ts` + `auth.ts` | 未开启 `HIDE_USER_API_KEY` 时，`Authorization` 里任意非访问码字符串都被当作"用户 Key"放行，配合 `X-Base-URL` 构成对任意地址的中转。 | 匿名中转。这是 NextChat"自定义接口 + 服务端代理绕过 CORS"的原有设计，修复会改变"只填自己 Key、不填访问码"的用户能否使用自定义接口，**本轮不改，列为待决策项**（第 6 节）。 |

## 4. 原则

- 先堵安全问题，再修正确性问题，最后删除；删除只针对没有调用方、或已确认失效/越界的功能。
- 不改聊天、图片、授权的用户可见流程；S5 等需要产品取舍的改动只记录，不实施。
- 每阶段都跑 `tsc`、`eslint`、`jest`、`vercel-build`。

## 5. 修复方案

### 阶段 1：安全

- **S1**：通用代理区分"服务端配置的上游"和"客户端指定的上游"。只有当上游地址规范化后等于服务端 `BASE_URL` 时，才注入服务端 Key；客户端指定的上游只转发用户自己的 Key（`X-User-Api-Key`）或原始 `Authorization`（访问码除外）；协议限制为 http/https。新增单测。
- **S2**：删除 `/api/proxy/{azure,google,openai,anthropic,alibaba}` 和 `/sharegpt` 改写，保留 `/google-fonts`（`home.tsx` 在用）。
- **S3**：`artifacts` 的 `POST` 走 `auth()`，`GET` 保持公开（分享链接要能打开）。
- **S4**：`model-info/refresh` 走 `auth()`。

### 阶段 2：正确性

- **B1**：`ChatOptions` 新增 `plugins?: string[]`，`LLMConfig` 携带完整模型参数。`ChatGPTApi`/`BaseOpenAICompatibleApi` 改用"全局默认配置 + `options.config`"，不再读取当前会话；工具只取 `options.plugins`。`getHeaders` 新增参数 `{ omitUserApiKey }`，由 RAGFlow 客户端显式传入。`onUserInput` 传入目标会话的插件；标题和记忆总结不带工具。
- **B2**：`[provider]` 路由把 `ApiPath.RAGFlow` 交给通用代理，上游固定为 `RAGFLOW_URL`，鉴权使用 `ModelProvider.RAGFlow`（服务端 Key 取 `RAGFLOW_API_KEY`）。未配置 `RAGFLOW_URL` 时返回明确错误。

### 阶段 3：移除失效与越界功能

- **R1**：删除 ShareGPT 分享（`ClientApi.share`、导出面板的分享按钮及文案、改写规则）。
- **R2**：删除上游版本检查（`getLatestVersion`、Tauri 通知、设置页"检查更新"），`update` store 只保留余额查询。设置页版本行改为显示构建的 commit 短哈希。
- **R3**：删除 `src-tauri/`、`app:*`/`export*` 脚本、`@tauri-apps/*`、`BUILD_APP`/`BUILD_MODE=export` 分支、`window.__TAURI__` 声明与分支、`utils/stream.ts`（流式请求直接使用 `window.fetch`）、`utils/platform.ts` 中的 `clientUpdate`/`adapter`、`data-tauri-drag-region` 属性，`config/build.ts` 不再读取 `tauri.conf.json`。
- **R4**：删除 `RAGFLOW_BASE_URL`，占位符改为通用示例。

### 阶段 4：死代码

按 3.4 删除未使用的导出、文件和依赖，合并重复类型（`typing.ts` 的 `ROLES`/`MessageRole`/`RequestMessage` 删除，以 `client/api.ts` 为准），桶文件只保留有调用方的再导出；`react-router` 改为 `react-router-dom`；删除 `trimTopic`。

## 6. 待决策（本轮不实施）

1. **S5 匿名中转**：建议在服务端要求访问码（`NEED_CODE` 开启时），客户端访问码不再只放在 `Authorization` 中，而是单独放进请求头，`Authorization` 留给用户 Key 和插件 Token。代价是：只填自己 Key、没有访问码的用户将无法使用自定义接口和插件。
2. **`docs/` 归档**：是否把 `docs/01–09` 移进 `docs/archive/`。

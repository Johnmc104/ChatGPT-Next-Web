# 代码结构分析与重构计划

## 1. 范围与基线

本报告以 Vercel 部署的 Web 应用为唯一目标。基线提交 `5a7ce312`，`app/` 共 169 个 TS/TSX 文件，约 28.7k 行。`yarn lint` 当前 0 error、2 warning（均为未使用的 `eslint-disable` 指令）。

目标：在不改变用户可见行为、Provider payload、授权判断、SSE 停止/错误恢复与图片资源语义的前提下，降低少数超大模块的耦合与认知负担，使后续迭代更安全。本轮为纯结构重构，不新增功能。

## 2. 现状盘点

工程已完成多轮分层拆分，整体结构健康：

- `app/domain/`：纯业务逻辑（model、message、media、endpoint、auth、settings），无 React、无网络依赖，单测覆盖充分。
- `app/services/`：带副作用的服务层（chat/stream、media/image、endpoint/test 等）。
- `app/store/`：Zustand store，`chat.ts` 已与 `chat-actions.ts`、`chat-migrations.ts`、`chat-types.ts` 分离。
- `app/components/`：聊天视图已拆出 `chat-header`、`chat-input`、`chat-list`、`chat-message-item`、`chat-modals`、`chat-actions` 以及 `chat-tts`、`chat-images`、`chat-keyboard-shortcuts` 等 hook/helper。
- `app/client/platforms/`：`base.ts`（470 行）承载共享 SSE/工具逻辑，`openai.ts` 复用基类。

## 3. 核心问题：`_Chat` 组件

`_Chat()`（`chat.tsx` 152–952 行）是唯一明显超出合理规模的单元：

- 单组件约 800 行，包含约 30 个 `const`/`useCallback`/`useMemo`、3 个 `useEffect`、1 个约 230 行的 JSX return。
- 混合了多个关注点：消息收发（`doSubmit`/`onResend`/`onUserStop`）、消息编辑与右键菜单（`onDelete`/`onPinMessage`/`onEditMessage`/`onRightClick`）、滚动与渲染窗口（`renderMessages`/`messages`/`onChatBodyScroll`）、输入处理（`onInput`/`onInputKeyDown`）、未完成输入持久化、设置链接命令。
- 已有的 `chat-*` 拆分证明这是项目认可的方向，但消息动作与窗口逻辑仍留在主组件内。

其余大文件要么是资源文件（locales），要么已按方法/职责组织清晰（`openai.ts`、`base.ts`、`chat-actions.ts`），本轮不动，避免为拆而拆。

## 4. 重构方案

仅针对 `_Chat`，抽取为纯 hook，保持组件 JSX 与渲染行为完全不变：

### P1 — 抽取消息动作 hook（本轮实施）

新建 `app/components/chat-message-actions.ts`，导出 `useChatMessageActions(...)`，封装 `deleteMessage`、`onDelete`、`onResend`、`onPinMessage`、`onEditMessage`、`onRightClick`、`onUserStop`。这些 handler 彼此关联、依赖 `chatStore` 与会话消息，是最内聚、最易安全抽取的一组。

约束：

- 纯搬移，不改任何逻辑分支，包括 `authorizationError` 读取、ChatControllerPool、`stopStreaming` 行为。
- 不改变 payload、授权阻断、停止/错误恢复。
- 入参/返回值签名与原 handler 一致，`_Chat` 内调用点不变。

### P2 — 抽取渲染窗口 hook（本轮实施）

新建 `app/components/chat-render-window.ts`，导出 `useChatRenderWindow(...)`，封装 `msgRenderIndex`/`setMsgRenderIndex`、`renderMessages`、`messages`、`onChatBodyScroll`、`isAttachWithTop`、`scrollToBottom` 相关派生逻辑（与 `useChatScroll` 协作部分保持接口不变）。

### P3 — 清理 lint warning（本轮实施）

移除 `app/components/exporter.tsx` 与 `app/layout.tsx` 两处未使用的 `eslint-disable` 指令，使 lint 达到 0 warning。

### 不在本轮范围

- 不拆 `openai.ts`、`base.ts`、`chat-actions.ts`、locales。
- 不改视觉与交互。
- 不引入新 Provider 协议或改默认模型语义。

## 5. 验收

每阶段集中修改后执行：

1. `./node_modules/.bin/tsc --noEmit`
2. `yarn lint`
3. `yarn test:ci`（或 Node 26 Docker 定向用例）
4. `yarn vercel-build`

行为等价判据：`_Chat` 渲染输出、所有 handler 行为、store 调用序列不变；现有 Jest 全绿；无新增 warning。

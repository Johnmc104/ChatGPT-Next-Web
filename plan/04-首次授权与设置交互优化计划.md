# 首次授权与设置交互优化计划

## 1. 当前问题

首次进入应用时，`Home` 在 effect 中异步调用 `/api/config`，而 `AuthPage`、`Chat` 和 `Settings` 会立即读取默认状态。默认 `needCode=true`、`hasServerApiKey=false`，因此用户可能在配置尚未返回前看到错误提示，或输入访问码后仍被判定为未授权。`AuthPage` 的提交逻辑、设置页的访问码编辑和聊天页的授权提示也各自维护错误文本，缺少统一状态。

## 2. 目标交互

授权状态采用 `idle → loading → ready/error` 状态机：

1. 首次加载显示轻量骨架和“正在读取服务配置”，不显示误导性的未授权错误。
2. 配置成功后，根据“需要访问码、服务端是否有 Key、是否允许用户 Key”显示对应字段和引导。
3. 点击确认或按 Enter 时执行同一条校验流程；按钮在提交期间禁用，错误显示在字段附近并保留重试入口。
4. 服务端拒绝、服务端未配置 Key、访问码错误、网络失败分别给出不同提示，并避免回显密钥。
5. 设置页复用同一授权状态，修改访问码或自定义接口后提供“验证连接”操作。

## 3. 分阶段任务

### A1：状态与加载

- `useAccessStore` 增加配置加载 Promise、状态、错误和重试方法。
- `AuthPage` 等待配置 ready 后再进行授权判断。
- `Chat` 在配置未完成时显示加载状态，不把默认值当作最终授权结果。

### A2：表单与错误

- 抽取 `AuthForm` 的提交、Enter 键和字段校验逻辑。
- 添加访问码必填、API Key 格式、接口 URL 格式校验。
- 统一错误码到本地化文案，网络错误提供重试按钮。

### A3：设置引导

- 把“自定义接口”和“自定义模型”分为两个设置区块。
- 在接口配置下显示 Provider、Endpoint、API Key、验证连接和最近一次验证结果。
- 在模型配置下显示模型 ID、展示名、Provider、能力声明和启用状态。

## 4. 验收标准

清空本地存储后首次进入，配置加载期间不会出现错误闪烁；输入正确访问码后一次进入聊天；错误访问码不会发送模型请求；网络失败可重试；设置页和登录页显示一致的授权状态。新增组件测试覆盖加载、成功、失败、Enter 提交和重复点击。

### 2.2 环境变量模板（P1）

| # | 问题 |
| --- | --- |
| E1 | 同时存在两份模板：`.env.template`（通用）和 `.env.local.example`（OpenRouter 示例）。后者在 `BASE_URL` 示例里写入了一个具体的 Cloudflare 账号 ID，属于个人标识，不应出现在公开仓库中。 |
| E2 | `.env.template` 缺少代码实际读取的变量：`CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_KV_NAMESPACE_ID`、`CLOUDFLARE_KV_API_KEY`、`CLOUDFLARE_KV_TTL`（Artifacts 分享）、`GA_ID`、`GTM_ID`；`PROXY_URL` 的示例值写成了 `http://localhost:7890`，照抄会让服务端所有请求都去走一个不存在的代理。 |
| E3 | 没有任何机制保证模板与代码同步，新增变量时容易遗漏。 |

### 2.3 构建、测试与提交配置（P1/P2）

| # | 位置 | 问题 |
| --- | --- | --- |
| C1 | `.babelrc` + `next.config.mjs` `experimental.forceSwcTransforms` | 存在 `.babelrc` 时，Next 会改用 Babel 编译，项目再用实验性开关强制切回 SWC；Jest 走的是 `next/jest`（SWC），同样不读 `.babelrc`。这个文件没有任何实际作用，却需要一个实验开关来抵消它。 |
| C2 | `app/polyfill.ts` | 为 `Array.prototype.at` 打补丁。Next 16 支持的浏览器全部原生提供该方法，补丁不会生效。 |
| C3 | `jest.config.ts` `collectCoverageFrom` | 只统计 5 个文件，其中 `app/api/provider.ts` 根本不存在。CI 报告的"覆盖率"不代表整个代码库。 |
| C4 | `.lintstagedrc.json` | 只检查 `app/**`，`test/**` 的改动提交时不会经过 ESLint 和 Prettier；同时还对 `.md`/`.json`/`.html` 文件运行 ESLint，没有意义。 |
| C5 | `package.json` | `"private": false`，存在被误发布到 npm 的风险；`"license": "mit"` 不是规范的 SPDX 写法（应为 `MIT`）。 |
| C6 | `scripts/` | `delete-deployment-preview.sh` 服务于已删除的 Vercel CLI 部署 job；`init-proxy.sh` + `proxychains.template.conf` + `proxy-dev` 脚本是上游给 WSL 用的代理辅助，依赖未声明的 `proxychains` 命令，当前开发流程（eda 上的 Docker）用不到。 |
| C7 | `.gitpod.yml` | Gitpod 自动生成的配置，不属于当前开发流程。 |
| C8 | `.gitignore` / `.dockerignore` | 前者没有忽略构建时生成的 `.swc/` 和个人工具目录 `.vtool/`；后者没有排除 `docs/`、`plan/`、`test/`、`.github/`，构建镜像时会把它们一起发给 Docker。 |

### 2.4 源码目录组织（P2）

| # | 问题 |
| --- | --- |
| D1 | `app/lib/` 只有一个文件 `audio.ts`（实时语音的 `AudioHandler`），同时 `app/utils/audio.ts` 也存在（TTS 播放器）。两个同名文件分散在两个目录，`lib/` 也没有和 `utils/` 区分开的含义。 |
| D2 | `app/store/chat-actions.ts`（LLM 请求、标题与记忆总结、MCP）与 `app/components/chat-actions.tsx`（输入框上方的操作按钮）同名，但职责完全不同，搜索和阅读时容易混淆。 |
| D3 | `app/utils.ts`（桶文件）与 `app/utils/` 目录并存。`import "../utils"` 解析到的是文件而不是目录。这是现有约定，改动面大、收益小，**本轮不改**。 |

### 2.5 eda 本机环境（非仓库内容）

`node_modules`、`coverage/`、`.swc/`、`next-env.d.ts` 的属主是 root，是早期以 root 身份运行容器留下的。普通用户无法清理，也无法 `yarn install`，所以改依赖时只能以 root 身份运行容器（`plan/16` 阶段 3 就遇到了）。

## 3. 修复方案

1. **对外说明**：
   - README 的部署按钮和 Issues 链接改为本仓库；删除指向上游的演示链接、自引用的 English 链接和 Zeabur 按钮；
   - "保持更新"改为说明本仓库已独立演进、不再同步上游；
   - 容器部署改为用本仓库的 `Dockerfile` 构建，`docker-compose.yml` 改为 `build: .`；
   - 本地部署改为 `yarn install && yarn build && yarn start`；
   - 删除 `scripts/setup.sh`、`docs/guides/bt-cn.md`、`docs/images/bt/`、`docs/guides/cloudflare-pages-{cn,en}.md`；
   - 修正同步指南的图片路径；
   - `CODE_OF_CONDUCT.md` 的联系方式改为本仓库 Issues；
   - 删除 `issue-translator.yml`。
2. **环境变量**：
   - 合并为唯一的 `.env.template`：补齐缺失变量，`PROXY_URL` 改为留空，按功能分组，把 OpenRouter 示例写成注释；
   - 删除 `.env.local.example`；
   - 新增 `test/env-template.test.ts`，双向检查模板与 `app/config/server.ts`、`build.ts` 读取的部署配置变量一致（`NODE_ENV`、`VERCEL`、`BUILD_MODE` 这类平台或构建变量除外）。
3. **构建与提交**：
   - 删除 `.babelrc`、`forceSwcTransforms` 和 `app/polyfill.ts`；
   - `collectCoverageFrom` 改为统计整个 `app/`（排除 locales、masks 数据、图标、类型声明）；
   - lint-staged 覆盖 `app/` 和 `test/` 的 TS/JS 文件，JSON/CSS/SCSS 只跑 Prettier；
   - `package.json` 改为 `private: true`、`license: MIT`，删除 `proxy-dev` 脚本和相关的代理辅助文件；
   - 删除 `delete-deployment-preview.sh` 和 `.gitpod.yml`；
   - 补齐 `.gitignore` 和 `.dockerignore`。
4. **目录组织**：`app/lib/audio.ts` 移为 `app/utils/realtime-audio.ts`，删除 `app/lib/`；`app/store/chat-actions.ts` 改名为 `app/store/chat-requests.ts`（含导出的 `createChatActions` 等名称不变，只改文件名）。
5. **eda 环境**：在容器中以 root 删除 `coverage/`、`.swc/`、`next-env.d.ts`，并把 `node_modules` 的属主改回当前用户。之后容器一律以普通用户身份运行。
6. **AGENTS.md**：补充新增的约定（唯一环境变量模板、`noUnusedLocals`、提交钩子范围、文档位置）。
